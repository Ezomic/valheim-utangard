#! partner paired-kill-credit-killer
# Kill credit, TWO CLIENTS: the side that stands by. LHM-36.
#
# Nothing to press here. Devkit runs this on client B the moment paired-kill-credit-killer.txt
# starts on client A, and A's file spawns, summons and kills everything. Read that file's header
# for why the pair exists, what the first run showed and how it is run (own-profile\pair.ps1, then
# one Run on A); this one is the short half. It lives in Utangard's scenarios with its partner,
# because two of the three mods it checks are Utangard's.
#
# This character never hits anything, never spawns anything and summons nothing. God mode and
# ghost mode are on, so nothing turns on it and it cannot become an attacker by accident. What this
# machine may still have is a boss: the machine that has A's altar spawns the boss, and on the first
# run, 2026-09-30, that was this one, for both Eikthyrs. So nothing here assumes which machine the
# server gives the bosses to. The greydwarfs are different: A spawns them, so they are A's, and A
# checks that before each kill.
#
# WHERE IT STANDS. It stays wherever this character is until A sets rig_kc_ready, and only then
# comes over with `partner`, three metres to A's left and facing A's way, and turns to the pole A
# put between itself and the altar. Standing and looking there is what a creature with a death
# animation would need for this machine to run its death as well; Greydwarf and Eikthyr have none,
# so for them it changes nothing (see WHAT IT CANNOT SEE).
#
# What it proves from this side, whichever machine had the bosses:
#   - Utangard's boss credit ran here once for every death this machine ran as the owner and for
#     no other: bosscredit equals asowner, for Greydwarf and for Eikthyr, before the run and after.
#     On the first run that meant two Eikthyr deaths owned here and two credits run here.
#   - It ran none of A's greydwarf deaths (they were A's), fed no sapling, and counted no kill in
#     this character's own tally: it hit nothing.
#   - Vandi's record for this character did not move, whoever had the bosses: Vandi credits the
#     summoner, and this character summoned nothing. On the first run this machine had both bosses
#     and wrote the credit, to A's id, and this record stayed where it was.
#   - One line per creature says whether this machine ran a death it did not own during the run:
#     `nonowner=` from `utangard deaths <creature> since <notowner>`, and `printed nonowner= yes`
#     fails the step when the line is missing. It speaks for this machine only; A's log carries
#     A's. With these two creatures it reads 0, and says the refusal of a machine that does not
#     have the creature was NOT exercised.
#
# WHAT A BROKEN BUILD READS, on this side
#   - Utangard's KillCredit asking about the owner in its postfix, which credits nobody: when this
#     machine had a boss, `went erule bosscredit=(\d+) same` reads "went from 2 to 0" or the like.
#   - Any credit on a machine that does not have the creature: bosscredit above asowner here, so
#     `went ... same` reads "went from N to" a larger number, or fedhere rising. That needs this
#     machine to run a death it did not own, which these creatures never give it.
#   - A Vandi that credits the player at the machine that ran the death instead of the summoner:
#     when this machine had the boss, `went vandi ... same` reads +2 here and A's reads +0.
#   - `went gown ... same` rising: this machine had a greydwarf A spawned. Not a mod failure; A's
#     `printed nearest=here` should have failed first. Run the pair again.
#
# WHAT IT CANNOT SEE
#   - A's side of anything. A's counts are A's to check, and the totals over both machines (Vandi's
#     record for A, A's tally, the sapling's own count) are read there.
#   - A machine crediting a creature it does not have, for the reason in the killer's header.
#   - Deaths it ran that were not A's kills. Nothing else should die within reach during a run:
#     A sends every wild creature within 60 m away before each greydwarf, and the sapling's
#     callers are sent away with them.
#
# WHAT IT LEAVES BEHIND: this character beside A on A's fresh ground, in god mode and ghost mode.
# Devkit empties the pack at the end and hands back its kit.

# The three signals this side waits for. It starts in the same second as A's file, and a
# `waitfor` on a key an abandoned run left set would return before A's own clearing got here.
# A key removed from a client is only gone here once the server's answer comes back, which is
# what the wait is for. A sets none of them for many seconds yet, so this cannot clear a live one.
unkey rig_kc_ready
unkey rig_kc_grey
unkey rig_kc_boss
wait 2

god
ghost

# The numbers before, all of them this machine's own. Nothing here is absolute: the counts run
# from the start of the process and the records from whenever this character first played here.
# The exception is the rule, which holds at any moment: noted as asowner, then compared with
# bosscredit from the same line, so `went` reads "went from asowner to bosscredit".
console utangard deaths Greydwarf
note gnot notowner=(\d+)
note gown asowner=(\d+)
note gkills kills=(\d+)
note grule asowner=(\d+)
went grule bosscredit=(\d+) same

console utangard deaths Eikthyr
note enot notowner=(\d+)
note erule asowner=(\d+)
went erule bosscredit=(\d+) same

console vandi
note vandi defeated_eikthyr=(\d+)

# Before the sapling exists, so only the count this machine keeps of its own feeds.
console vaettir sapling
note fedhere fedhere=(\d+)

waitfor rig_kc_ready 300

# Beside A now: three metres to A's left, clear of the sapling A plants two metres to its right,
# and facing the way A faces.
partner -3

# Look where the killing happens: the pole stands between A and the altar. A copy of a creature
# nobody is looking at may not be animated at all, and then it never reaches its Die event.
face wood_pole2
wait 1

key rig_kc_watching

# ---------------------------------------------------------------- five greydwarfs

waitfor rig_kc_grey 300

# A's last kill ended when the body was gone on A. Anything this machine does about it happens
# before A's removal of that body reaches here, and the removal was sent before the signal, so
# this is slack rather than a guess.
wait 3

# The last line says whether this machine ran a greydwarf death it did not own during the run.
console utangard deaths Greydwarf since $gnot
printed nonowner= yes

# A's greydwarfs, run on A: none here as owner, and no kill for a character that hit nothing.
went gown asowner=(\d+) same
went gkills kills=(\d+) same

# The rule, whatever this machine ran.
note grule asowner=(\d+)
went grule bosscredit=(\d+) same

console vaettir sapling
went fedhere fedhere=(\d+) same

key rig_kc_b_grey

# ---------------------------------------------------------------- two Eikthyrs

waitfor rig_kc_boss 300
wait 3

# Whether this machine ran an Eikthyr death it did not own during the run, in words.
console utangard deaths Eikthyr since $enot
printed nonowner= yes

# The rule on this machine, whether it had both bosses, one or neither. A checks the same on its
# side, so between them every death that ran as an owner got one credit.
note erule asowner=(\d+)
went erule bosscredit=(\d+) same

# This character summoned nothing, so Vandi's record for it stays, whichever machine had him.
console vandi
went vandi defeated_eikthyr=(\d+) same

key rig_kc_b_done
