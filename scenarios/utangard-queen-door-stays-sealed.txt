#! nostage
# Utangard - the Queen's door stays sealed while its biome is locked.
#
# Same premise as utangard-altar-in-a-locked-biome, and the same keys cleared: the Deep North,
# shut on purpose. The Queen's entrance is spawned there, because the rule reads the biome the
# door stands in, not which boss is behind it.
#
# A keyed door opens two ways and vanilla spends the key inside both before the door moves: the
# key used from the hotbar (Door.UseItem) and E with the key in the pack (Door.Interact). So both
# are tried, and after each the door is still shut and the Sealbreaker is still carried.
#
# The names were asset data nobody had seen when this was first written, and the run of
# 2026-09-28 settled both. The location is Mistlands_DvergrBossEntrance1: it placed, and its
# dungeon DG_DvergrBoss generated 45 rooms. The door is dungeon_queen_door, not DvergerBossDoor,
# which the first version guessed and every door step then failed to find. Utangard's own line on
# world load names it, read off ZNetScene's prefabs by the Sealbreaker it wants: "Boss doors kept
# sealed in a locked biome: dungeon_queen_door (DvergrKey)". So that line is still where to look
# if this ever stops finding the door.
#
# The door steps search 100 m, not the 60 the first version used. TestSpawnLocation clamps a
# location into its zone by the location's radius, and this one's is 32, the whole zone, so it
# lands on the zone's centre however far ahead it was asked for: 25 m from the player in that run,
# not 30 m ahead. The dungeon keeps its rooms inside that zone's 64 m square (its "Bounds diff"
# line in Player.log), so the door is within about 70 m of anybody standing in the zone, and the
# rest of the 100 is room for height.
#
# NO STAGE. The `#! nostage` line at the top turns off the ground Devkit makes ready before the
# first step, and there is no `stage` after `biome` either, because a location wants the world's
# own ground under it. It levels its own pad with the game's older terrain system, and the game
# applies that before the terrain compiler a stage writes to, so on staged ground the stage's
# change is added on top of the pad: where the stage raised the slope a metre, the pad comes out a
# metre above the entrance's foot, and where it lowered it, a metre below. On the world's own
# ground the pad is level with the entrance, which is what `location` is for.

clear
god
ghost

unkey defeated_fader
unkey utangard_open_defeated_fader
unkey wither_open_defeated_fader
unkey utangard_first_defeated_fader
unkey utangard_p_$player_defeated_fader
wait 1

biome DeepNorth
wait 3
location Mistlands_DvergrBossEntrance1 30
wait 3
give DvergrKey:1
dooris dungeon_queen_door shut 100

# Shut: the key from the hotbar.
centre The seal will not break no
door dungeon_queen_door DvergrKey 100
centre The seal will not break here yet yes
wait 1
dooris dungeon_queen_door shut 100
carrying DvergrKey 1

# Shut: E, with the key in the pack.
door dungeon_queen_door 100
centre The seal will not break here yet yes
wait 1
dooris dungeon_queen_door shut 100
carrying DvergrKey 1

# Open, the way the group's Fader kill would leave it. Whether the key is spent now is the
# door's own m_consumeKey, vanilla's business, so it is not asserted.
key utangard_open_defeated_fader
wait 1
door dungeon_queen_door 100
centre The seal will not break no
wait 2
dooris dungeon_queen_door open 100

unkey utangard_open_defeated_fader
